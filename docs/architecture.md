# LPG Manager architecture

Start here before changing a workflow. This map reflects the repository implementation reviewed on **2026-10-19**. Customer reporting/editing and shared transaction inspection are deployed to the existing Azure backend and Cloudflare Worker, with live Auth/API and published-browser acceptance using cleaned-up fixtures. The purchase workflow separates expected-quantity receipt, transport funding, cancellation reversals and transit cost closure. Its deployment was verified against VPS PostgreSQL 17.6 and real Auth/PostgREST with isolated fixture businesses and concurrent sessions. Source and ordered SQL migrations are authoritative. Broader modal/browser scenarios use API fixtures; physical printing is a separate acceptance boundary. Supabase MCP tools were unavailable; deployment verification used the established SSH/SQL path.

## Runtime and dependency boundaries

```mermaid
flowchart LR
    Host[Static hosting: local Nginx or Cloudflare] --> UI[React browser app]
    UI -->|session and public key| Gateway[Supabase Envoy gateway]
    Gateway --> Auth[Supabase Auth]
    Gateway --> REST[PostgREST: reads and RPCs]
    Auth --> DB[(PostgreSQL)]
    REST --> DB
    UI -->|committed receipt| Bridge[Windows localhost print bridge]
    Bridge --> USB[Winspool RAW / USB printer]
    UI -->|committed receipt| Dialog[Browser print dialog / installed printers / PDF]
```

- The app is a React 19 / TypeScript SPA built by Vite, using React Router's `HashRouter`, TanStack Query, custom CSS, Lucide icons and toast feedback. [App.tsx](../src/App.tsx) composes the query client, Auth provider, layout and route tree. Page modules use module-level `React.lazy` imports; Vite splits their code, shared dependencies and page styles. Suspense around the layout outlet retains navigation during page loading; the outer boundary covers public Auth pages. Providers and the query cache remain above both boundaries. [Route-loading browser checks](../tests/route-loading.browser.cjs) cover cold startup, deferred assets, delayed imports, navigation and direct reloads with API fixtures. There is no application HTTP backend between the browser and Supabase.
- [Domain hooks](../src/hooks/) own operational Supabase queries and mutations. Pages and feature components manage forms, cart state and presentation. Shared domain types live in [src/types](../src/types/); employee, customer and POS contracts currently also live in their hooks. [src/lib](../src/lib/) holds phone/currency helpers, capability mappings and receipt clients.
- [Layout](../src/components/Layout.tsx) provides permission-filtered navigation, the current page title, theme control, a permission-gated dealership wallet, and the sidebar business/account sign-out menu. On mobile screens, navigation and account controls collapse into an off-canvas drawer toggled from the topbar hamburger menu. The shell contains a scrolling page area. Purchases shows four separated overview figures and compact company/status/date/truck cards with product lists and a single total cost row; complete product/financial details stay in its summary dialog. Its toolbar filters/searches the existing query result before sorting. Shared [control styles](../src/components/ui/controls.css) customize native select pickers where supported and retain native selection, keyboard and validation behavior; other browsers retain styled fields with system menus. [DatePicker](../src/components/ui/DatePicker.tsx) pairs native date typing/validation with a top-layer calendar that also works inside dialogs. Purchase dialogs keep actions visible while their forms scroll.
- PostgreSQL owns multi-table workflows through permission-gated `public` RPCs. Internal recorders and triggers live in unexposed `app_private`. A business RPC and its trigger effects form one database transaction; printing and Auth signup are separate operations.
- Shared layout rules in [index.css](../src/index.css) give `.page-content` the dynamic viewport's remaining space and ownership of page scrolling. The viewport declaration in [index.html](../index.html) opts into keyboard-driven content resizing on [supporting Android browsers](https://developer.chrome.com/blog/viewport-resize-behavior/). Pages grow with content; wide tables scroll inside `.table-scroll`, and dialogs scroll their bodies while retaining actions. Workspace container queries adapt multi-panel layouts to the width left by navigation. POS product cards have a maximum width; the desktop checkout sidebar fills the workspace height even when empty and keeps checkout at the bottom. All cart lines render without pagination; tall workspaces scroll the lines while retaining totals, and short workspaces scroll the cart body. Stacked POS layouts provide checkout/products shortcuts. Preserve these boundaries instead of adding page-specific viewport-height calculations.
- [supabase.ts](../src/lib/supabase.ts) builds one browser client from the Vite URL/public key. Development accepts the listed loopback gateways; production also accepts HTTPS self-hosted gateways. Cloud Supabase URLs and privileged secret/service-role keys are rejected. These are build-time settings.
- [compose.yml](../compose.yml) supplies local Nginx, Envoy, Auth, PostgREST, PostgreSQL, Realtime, Storage/imgproxy, Studio/meta, Mailpit, Edge Runtime and Supavisor. [compose.azure.yml](../compose.azure.yml) adds Caddy and production profiles/limits; the updater selects ten backend services, including Studio and postgres-meta. Production Studio uses the API origin with dashboard authentication; see [dashboard access](../deploy/README.md#production-dashboard). [wrangler.json](../wrangler.json) configures a separate static Cloudflare frontend. The bridge runs on the browser's Windows host, outside both stacks.
- Shared [page controls](../src/components/ui/Pagination.tsx) and [list state](../src/hooks/useListPage.ts) bound growing directories, selections, histories and editors. Full collections/drafts still drive summaries, ordering and totals. Customers uses tenant-scoped server aggregates and pages; Dashboard uses look-ahead sale pages. Customers and Inventory share [InventoryProductPicker](../src/components/inventory/InventoryProductPicker.tsx) and the dedicated saved-transaction detail modal; printing remains in its existing subsystem.
- Android/phone presentation stays in the existing CSS and components. `.mobile-record-table` presents labeled employee and fleet records below 600 CSS pixels while retaining desktop tables. Shared selects use `appearance: base-select` for touch and mouse input, retaining native pickers in unsupported browsers. Android fields follow the compact body text scale; iOS retains 16px fields to prevent focus zoom. Escape dismisses an open picker before its enclosing calendar or receipt dialog. `usePageSize` bounds phone directories without changing full-data totals or draft state. [Android browser checks](../tests/android.browser.cjs) cover every route, secondary tabs, empty data, navigation and forms using isolated API fixtures; [field checks](../tests/field-controls.browser.cjs) cover touch selection, keyboard use and nested pickers.
- Realtime and Storage are platform services, but the current application source has no subscriptions or Storage workflows. The Edge Runtime entrypoint is platform routing/authentication support, not an LPG business API. Refreshes use Query invalidation and polling.

## Data and transaction model

- Most business identities use `(tenant_id, entity_id)` keys and tenant-qualified relationships. A UUID alone is not a global ownership guarantee. Auth profiles connect real Auth users to one business; RBAC assignments/mappings determine access. Browser capability checks provide navigation, while database RLS, grants and RPC gates enforce authorization independently. See the [authorization guide](../supabase/authorization.md) rather than deriving access from role names or user metadata.
- Direct browser writes are restricted to zero-stock item registration, customer creation and authorized tenant printer upserts. Business mutations derive actor/tenant server-side; purchase RPCs insert referenced stock movements under purchase permission without granting general stock adjustment.
- `items` stores current filled/empty balances. Inserting `inventory_movements` applies deltas through a trigger. Sales couple header/lines, stock, customer transactions and dealership balance. Each sale captures its own retail/wholesale `sale_tier`; switching tier reprices the entire draft cart without changing a saved customer. The sale-tier migration must precede its dependent frontend. Purchases couple stock dispatch/receipt, transits and wallet effects. [Sales](modules/sales-and-inventory.md) and [purchases](modules/purchases-and-logistics.md) explain the different timing and accounting coverage.
- Employee payment and purchase activity records have explicit UPDATE/DELETE rejection triggers. Inventory and wallet/customer ledgers have restricted browser writes but do not share that immutability mechanism. Do not reconstruct balances from transaction sums without checking coverage and historical balances. Audit triggers cover brands and trucks; purchases also keep an attributed lifecycle/financial history.
- [Migrations](../supabase/migrations/) are an ordered chain: baseline domain DDL, fixes/customer rules, employee and printer additions, reconciliation, then authorization and printer-upsert grants. Later definitions supersede earlier functions/policies. Application SQL depends on Supabase roles, Auth schemas and extensions; it does not install a complete platform. Compose startup/build does not apply arbitrary application migrations to existing data.

## Workspace lifecycle and cache behavior

1. Auth restores/listens for the session. The provider reads the caller's `user_profiles`/tenant identity and calls `get_my_permissions`; profile and permissions refresh every 30 seconds and on query focus.
2. Registration signs up and signs in first, then calls `setup_business`. That RPC locks the Auth identity and atomically creates the tenant, profile, roles, mappings and owner assignment; a second membership is rejected. Signup itself is outside this transaction, so setup failure signs out but does not delete the Auth account.
3. Hooks perform RLS-scoped reads or RPC mutations and invalidate affected query families. Most domain keys are not tenant-keyed; the provider clears the cache when Auth user identity changes and on sign-out. Preserve that behavior when altering workspace admission/caching.
4. The query client defaults to five-minute freshness and one read retry. Dashboard, inventory and purchases add polling. Mutation invalidations must follow cross-module effects, not just the edited screen. There is no offline synchronization layer.

Dashboard's day boundary comes from the browser's local `startOfDay`, passed as UTC ISO to SQL; there is no fixed Bangladesh timezone calculation. Customer count is all tenant customers, and movement count counts rows, not cylinders. The sales feed reads eight completed sales per page plus a look-ahead row since that boundary, and falls back to header-only reads if embeds fail.

## Implemented scope and limits

Operational screens for sales, stock, customers, purchases, trucks/transits, brands/plants and employees/payments are implemented. Preserve these narrower boundaries:

- Finance is a placeholder route despite wallet/customer ledger tables and accounting effects. Business profile editing and Dashboard stock exceptions are placeholders.
- Inventory price/commission writes require inventory management capability and trusted OWNER membership. `get_product_inventory` returns the UI's edit-authority flag, current refill/package commission rates, prices, received-cost estimates less the matching manual rate and eight weekly aggregates. Commission history is append-only and has no browser read grants. Settings persists brand order; inventory groups by that order, then ascending product weight. Inventory history filters movements before pagination, reuses stock tiles for multi-selection, and opens existing sale/purchase dialogs under their original read permissions. See [sales and inventory](modules/sales-and-inventory.md). Staff invitation/role administration, general reporting and offline operation have no implemented UI/workflow. Employee profiles are not Auth memberships.
- Manual inventory adjustment has a hook/RPC but no exposed adjustment dialog. Purchase cancellation reverses recorded stock and payments atomically; transit completion releases trucks independently of confirmed expense closure.
- [zk-test/test.cjs](../zk-test/test.cjs) is a standalone ZKTeco ADMS listener prototype. It acknowledges/logs attendance pushes without persistence or employee/payroll integration.
- Receipts support the browser print dialog and direct Windows USB with manual bridge startup. Output preference is stored per tenant in this browser; USB configuration stays tenant-wide in Supabase. Receipt persistence, dialog opening, local job acceptance and physical output are distinct boundaries; hardware/origin requirements and uncertainty handling belong to the [printing guide](../print-bridge/README.md).
